If a page can't be read with web_fetch (blocked, or empty because JavaScript builds it), fetch the same URL from a Python script in the container (requests, with a normal browser User-Agent); if the content only appears after JavaScript runs, try a headless browser from Python (pip install playwright, then playwright install chromium). This container's network path re-signs TLS certificates with its own certificate authority: Python's requests already trusts it, Chromium doesn't until you add it. Before launching, find the CA bundle Python trusts (the REQUESTS_CA_BUNDLE or SSL_CERT_FILE environment variable, else /etc/ssl/certs/ca-certificates.crt) and import its certificates into Chromium's NSS database (apt-get install -y libnss3-tools; certutil -d sql:$HOME/.pki/nssdb -N --empty-password < /dev/null; then for each certificate split out of the bundle: timeout 10 certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n <name> -i <file> < /dev/null — certutil can wait forever on a prompt otherwise; the whole bundle takes a few seconds). Keep certificate checks on: never disable TLS verification. In general, give any command that might wait for input or the network a timeout and no stdin, so one stuck step can't eat the run. If it's still blocked, report it as blocked with the reason instead of retrying. Keep requests polite (a few per site, no hammering) and respect the site's terms.
